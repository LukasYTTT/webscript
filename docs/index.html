WebScript Documentation

Welcome to the official documentation for WebScript (wbs)!

WebScript is designed to make configuring web servers as simple as writing a basic script, while retaining the raw power of a full programming language. It is incredibly fast, powered by Go, and replaces complex Nginx setups.

💻 CLI Reference

Here are the fundamental commands you need to operate your WebScript server:

Command Description
wbs create Interactive wizard to generate perfect configuration files.
wbs service Installs WebScript as an automatic background SystemD daemon.
wbs -t <path> Syntax-checks your configuration files without starting the server.
wbs run <path> Manually start the server (use --dev for local testing).
wbs install <package> Installs an officially approved third-party package from the registry.

🏗️ How WebScript Works on Your Server

WebScript is not just a language; it is a full-featured web server and automation engine designed to replace traditional tools like Nginx or Apache while being significantly easier to configure.

1. The SystemD Daemon (wbs service)

When you run the command wbs service, WebScript installs itself as a background daemon using Linux SystemD.

  • Autostart: WebScript will automatically start whenever your server reboots.
  • Process Manager: If WebScript crashes for any reason, SystemD will immediately restart it.
  • Root Privileges: The service runs as root so it can bind to the protected web ports (Port 80 and 443).

2. Configuration Loading

When the WebScript daemon starts, it does not look for a single config.ws file. Instead, it scans the entire /etc/wbs/confs/ directory.

Every .ws file inside this directory is evaluated by the engine. You can split your domains into different files or group multiple domains in a single file!

3. Let's Encrypt Auto-HTTPS

WebScript handles SSL/TLS certificates completely automatically. You don't need to install certbot.

When a user connects to your domain via HTTPS (Port 443):

  1. WebScript checks if it has a valid Let's Encrypt certificate in its cache.
  2. If missing or expired, it temporarily pauses the user's connection.
  3. It asks Let's Encrypt for a new certificate via Port 80 (HTTP).
  4. WebScript intercepts this challenge automatically, downloads the certificate, and resumes the user's connection!
Cloudflare Warning: If you use Cloudflare Proxy (Orange Cloud), ensure your SSL/TLS encryption mode is set to "Full" or "Full (strict)". Setting it to "Flexible" will cause an infinite redirect loop!

4. The Routing Engine

  • Static Hosting (http.static): Serves files directly from the hard drive into the browser.
  • Reverse Proxy (http.proxy): Acts as a middleman. Receives the request on Port 443 and forwards it internally to your Docker container or Node.js app (e.g., Port 3000).
  • PHP FastCGI (http.php): Executes the php-cgi binary on your server.

📦 Custom Packages (Mono-Repo)

WebScript is a complete Domain-Specific Language (DSL). You can write reusable logic and share it with the world via the official WebScript Mono-Repo.

1. How the Package System Works

Whenever you define a variable or a function in the root scope of your .ws file, it is automatically exported. When someone installs your package, WebScript downloads your code and converts your package name into an object containing all exported functions.

2. Publishing Your Package

To ensure all packages are safe and centralized, WebScript uses an official Mono-Repo architecture. All packages live inside the official LukasYTTT/webscript repository inside the docs/packages/ folder.

  1. Fork the repository to your own GitHub account.
  2. Inside your forked repository, navigate to docs/packages/ and create a new folder with the name of your package (e.g., logger).
  3. Create an index.ws file inside that folder.
  4. Submit a Pull Request to the original repository.
# logger/index.ws

# Exported Variable
let defaultPrefix = "[INFO]"

# Exported Function
let logRequest = fn(domain, path) {
    print(defaultPrefix + " Incoming request for " + domain + " on path: " + path)
}

3. Using Packages

Any WebScript user can open their terminal and type:

wbs install logger

WebScript connects to the official repository and downloads ONLY your logger folder over fast HTTP. You can then import it:

# Import the package
import "logger"

http.server("example.com") {
    # Call the function from your package!
    logger.logRequest("example.com", "/*")
    http.route("/*", http.static("/var/www/html"))
}
